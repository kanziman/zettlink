# API 정가 약 2.4억 원, Bun의 Claude Code 하네스를 해부했습니다.

> https://www.youtube.com/watch?v=otMYg5NIsAo

## 요약

Bun의 창립자 재러드 섬너가 53만 줄의 Zig 코드를 Claude Code 에이전트 64개를 활용해 단 11일 만에 Rust로 이식한 사례를 상세히 분석한 영상이다. 단순히 에이전트 수를 늘리는 것이 핵심이 아니라, 시작 2분 만에 발생한 저장소 충돌 문제를 해결하기 위해 4개의 워크트리와 Dynamic Workflow 기반 병렬 구조를 설계한 것이 성공의 열쇠였다. PORTING.md와 LIFETIMES.tsv를 통해 에이전트의 입력을 표준화하고, 구현자와 평가자 에이전트를 분리하며, 약 1만 6천 개의 컴파일 오류를 작업 큐로 전환해 체계적으로 처리했다. 최종적으로 테스트·보안 리뷰·퍼징으로 구성된 검증 레이어를 통해 품질을 담보했으며, 이 경험을 개인과 소규모 팀이 적용 가능한 5단계 하네스 프레임워크로 정리하여 제시한다.

## 인사이트

- 64개 에이전트를 단순히 병렬 실행하면 공유 저장소 충돌이 시작 2분 만에 발생하며, 작업 공간 격리가 선행되어야 한다.
- 대규모 저장소의 디스크 제약으로 워크트리를 무한 확장할 수 없어, 4개의 샤드(워크트리)로 나누어 에이전트를 그룹화하는 현실적 타협이 필요했다.
- PORTING.md와 LIFETIMES.tsv 같은 구조화된 컨텍스트 문서가 에이전트 입력을 고정시키는 핵심 역할을 했다.
- 구현자 에이전트와 평가자 에이전트의 컨텍스트를 분리함으로써 역할 혼선을 방지하고 피드백 루프의 품질을 높였다.
- 약 1만 6천 개의 컴파일 오류를 그대로 방치하지 않고 작업 큐로 전환해 에이전트가 순차·병렬로 소진하는 구조가 마이그레이션 완주의 핵심이었다.
- 점진적 재작성보다 한 번에 전체 포팅하는 전략이 삭제될 임시 코드를 줄여 단·중기적으로 더 효율적임을 실증했다.
- 하네스는 단순 프롬프트가 아니라 '입력 고정 → 작업 공간 분리 → 통과 여부 판단 → 실패의 다음 실행 반영(루프)'으로 이루어진 전체 구조다.
